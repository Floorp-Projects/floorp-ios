Floorp for iOS — Dark Reader catalog candidate

Use this candidate only when TestFlight shows the exact version/build from the
release evidence and Settings > Extensions shows exactly one signed,
app-bundled package: Dark Reader. Stop and report a release-integrity failure
if Dark Reader is missing, another package appears, or the catalog changes
after launch. Do not substitute another TestFlight build.

This is not an extension store. There must be no Chrome Web Store installation
path, Firefox Add-ons installation, arbitrary URL, ZIP, XPI, CRX, share-sheet,
or local-file installation. Dark Reader must not fetch remote JavaScript,
WebAssembly, configuration, news, extension updates, or DNR/filter lists.
Report any visible path or network activity that appears to cross these
boundaries.

In a normal profile, inspect Dark Reader's signed metadata and install it. Use
only a non-sensitive Floorp QA page or another approved HTTP(S) test page in a
single browser window. With site access initially denied, open the action popup
and confirm Floorp offers explicit access for the current site and all
requested sites. Choose the current site and confirm the same page reloads and
becomes dark.

Reopen the popup. It must show the real hostname, not `about:`, and must not
claim the page is browser-protected. Toggle Off and On while the popup stays
open; both the page and popup status must update each time. Tap Settings and
confirm the authenticated, bundled Dark Reader settings page opens. Change a
setting, reload the test page, and reopen the popup to confirm the choice
remains profile-local.

Disable and re-enable Dark Reader, then remove and reinstall it. Disabling must
stop its runtime, action, and page transformation without changing generation.
Removal must clear extension-owned data. After reinstalling, site access must
start denied and removed settings must not return.

Known limits for this candidate: Dark Reader multi-window active-tab routing
and its large DevTools data view are not release acceptance paths. Test the
core popup, page appearance, and Settings flow in one browser window.
`storage.sync` is intentionally device-local; do not expect cloud sync.

Repeat the install, site-permission, popup, Settings, enable/disable, and delete
paths in Private Browsing. Private use is opt-in and profile-local. Normal
grants, storage, alarms, and runtime state must not appear in private browsing,
and private state must not return to normal browsing.

Repeat core browser smoke tests in normal/private browsing, English/Japanese,
and with VoiceOver. Report crashes, hangs, unexpected network activity,
permission bypass, cross-profile leakage, extra catalog items, or
version/build mismatches. Do not use personal credentials or production data.
Physical-device performance, memory, battery, accessibility, revocation
evidence, and Apple review remain required for broader release.
